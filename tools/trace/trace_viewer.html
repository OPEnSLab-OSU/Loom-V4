“Live captured bytes” counts requested sizes for individually observed blocks. “Heap bytes in use” comes from allocator totals and includes earlier allocations and allocator overhead. Those two numbers are different measurements.
What this recording can tell you

Captured blocks have an address, requested size, creation time, release time if observed, the instrumented call stack, object context when supplied, and a raw caller instruction address. A caller address can be resolved using the matching firmware ELF.

Object context tells you which object’s method was running; it does not prove that object owns the block. Static object labels are not counted as heap allocations. Retained blocks are not automatically memory leaks.

Initialization allocations, interrupt work, custom allocators and trace-saving internals are outside individual capture. Their memory can still contribute to allocator totals. Standby time is excluded. Lost events and incomplete calls are explicitly labelled.
